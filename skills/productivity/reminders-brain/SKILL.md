# 提醒事项大脑

把用户随手发来的任意一段中文文字，变成他苹果设备「提醒事项 App」里的一条日程；
并在此基础上纵览全局，主动提示、主动追问。

## ⚠️ 先读 `提醒事项/架构.md`

用户已有一条**现役且可用**的写入链路，不要另起炉灶：

```
微信 Clawbot ──入队──▶ 队列 43.160.249.235:8787
                          │ GET /claim（快捷指令定期认领）
                          ▼
              Apple 快捷指令 ──▶ 提醒事项「收集桶」──▶ 用户手机 ✅
```

**新增提醒 = 往队列入队**，但**必须先走去重协议**（见下方「一、写入」）。
Hermes 侧走本机 `http://127.0.0.1:8787`；公网那面是给 iPhone 快捷指令用的。

| 通道 | 状态 |
|---|---|
| 队列 + Apple 快捷指令 | ✅ **现役，用这条** |
| `remindctl`（macOS/EventKit） | 可行但用户当前不走 |
| iCloud CalDAV | ❌ 死路，苹果私有仓库，用户看不到 |

⚠️ **调试时不要 GET `/claim`** —— 那是认领语义，会把待写入条目消费掉。

## 何时使用

- 用户转发/粘贴一段含时间、地点、人物的文字 → 建提醒
- 用户问「我今天该做什么」「本周有什么」 → 出简报
- 用户问项目进展，或到了定期扫描时点 → 查停滞并追问
- 用户随口记一个想法 → 判断归类后落库

## 何时不用

- 用户只是在聊天、提问，没有要安排的事 → 正常回答即可
- 需要的是日历事件（有明确起止时段的会议）而非待办 → 用日历工具
- 用户明确说「不用记」→ 不要写入

## 一、随手转发 → 建提醒

### 解析规则

从文字中抽取：

| 字段 | 说明 |
|---|---|
| `事项` | 标题，必填。保留原文里的状态标记（如 ✅） |
| `日期` | 「7.2 / 7月2号 / 下周三」→ 就近的未来日期；今年已过则顺延明年 |
| `时间` | 「上午10:00」→ `10:00`；「下午3点」→ `15:00`；无 → 全天 |
| `地点` | 原样保留，写进备注 |
| `人物` | 原样保留，写进备注 |

**缺标题不可安排（必问）；缺日期要问；地点/人物可空。**
有歧义（尤其是具体哪天）**先问，不要猜**。

### 写入 —— 三步，别跳步

鉴权：`X-Queue-Token: <token>`，token 读自文件 `~/.reminder-queue/token`。

**第 1 步 `GET /pending`** —— 看队列里有没有同一件事，防重复入队。

**第 2 步 `GET /snapshot`** —— 拿设备上已有的提醒快照比对：
- 标题相似度 `difflib.SequenceMatcher`，**≥ 0.75 视为同一件事**
- 再比时间，判定是**重复**（放弃）／**冲突**（问用户）／**改期**（带 `replace: true`）

**第 3 步 `POST /push`**：
```json
{"title": "孙建亚老师 家前采时间确认",
 "due": "2026-07-02 10:00", "remind": "2026-07-02 09:00",
 "list": "收集桶",
 "notes": "人物：孙建亚老师｜地点：绿洲比华利花园931号楼",
 "source": "hermes-vps", "replace": false}
```

- `due` 到期、`remind` 提前提醒，两者独立；采访/拍摄/见面类默认提前 1 小时。
- **不要跳过前两步直接 POST** —— 会在用户设备上堆重复条目。
- **写入不是即时的**：快捷指令按自己的周期认领。回执要说「已排入队列，
  稍后出现在你的『收集桶』」，**不要说「已经在你手机上了」**。
- ⚠️ **任何情况下都不要 GET `/claim`** —— 消费型，一读就把用户待收的提醒
  吃掉。要查就用 `/pending` 或 `/snapshot`。
- 写完在 `提醒事项/日程.md` 追加一条登记。

### 回执

确认已安排（事项／时间／地点／提前提醒），然后**顺带做一次第二节的大局提示**。

## 二、主动大局管理

每次有新输入、或用户喊「看看」时，扫 `提醒事项/日程.md` 与 `项目跟踪.md`，主动给出：

- **今天／本周**该做的事
- **48 小时内到期** 与 **已过期未完成**
- **时间冲突**（同一时段两件事）
- **停滞项目**：见下一节

不要每次都把全部内容念一遍——只说需要用户现在采取行动的部分。

---

## 三、项目停滞主动追问

```bash
python3 提醒事项/scan.py            # 扫描并打印
python3 提醒事项/scan.py --remind   # 扫描并把追问写成提醒
```

`scan.py` 读 `项目跟踪.md`，找出「上次更新」超过阈值（默认 7 天）的项目，
生成一条「X 项目已 N 天无进展，卡在哪？」的提醒。

挂成定时任务（每周一早 9 点，推送到微信）：

```bash
hermes cron create "0 9 * * 1" \
  "运行 python3 提醒事项/scan.py --remind，然后把停滞项目和建议汇报给我" \
  --name "周一项目盘点" --deliver weixin
```

## 四、每日简报

数据源用队列的**只读**接口，三者叠加：

| 来源 | 内容 |
|---|---|
| `GET /snapshot` | 设备上已有的提醒（Mac 端上传的快照）← 主力 |
| `GET /pending` | 还在队列里、尚未同步到设备的 |
| `python3 提醒事项/scan.py` | 项目停滞 |

⚠️ **不要用 `/claim`**（消费型），**也不要用 `brief.py` 的 CalDAV 路径**
（读的是废仓库幽灵数据）。

```bash
hermes cron create "0 8 * * *" \
  "读 提醒事项/日程.md 并跑 python3 提醒事项/scan.py，汇总成简报发我" \
  --name "每日简报" --deliver weixin
```

## 五、随手记自动归类

用户随口一句想法，判断它属于哪类，落到对应文件：

| 判断 | 去处 |
|---|---|
| 有时间点、要执行 | → 建提醒（第一节） |
| 某个项目的进展／决定 | → `项目跟踪.md` 对应行 |
| 采访对象信息（地址／联系方式／状态） | → `联系人.md` |
| 素材、灵感、参考 | → `素材.md`，注明日期与来源 |

**判断不了就问一句**，不要默认丢进提醒事项制造噪音。

## 六、联系人 / 嘉宾库

`提醒事项/联系人.md` 以表格维护采访对象。每次建采访类提醒时，
顺带把人物、地址、时间、状态补进去，支持「上个月见了谁」这类回溯查询。

---

## 规则

1. 用户在本 group 粘贴的文字，**默认意图就是要安排进提醒事项**。
2. 关键信息有歧义（尤其日期）**先问再做**。
3. 每次写入后给明确回执，并顺带做一次大局提示。
4. 凭据只从环境变量读，**绝不写进文件或提交到仓库**。
5. 不确定该不该记的，问一句，别猜。
