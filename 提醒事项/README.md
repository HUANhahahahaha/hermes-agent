# 提醒事项 · 执行规则（Charter）

> 本文件是「提醒事项」这个 group 的**长期生效操作规则**。我（助手）每次在本 group 工作时都先读它，再按规则执行。
> 维护人：用户（ifooon@gmail.com）　|　最后更新：2026-06-22

---

## 0. 这个 group 是干什么的

用户在这个 group 里粘贴的**任何文字**，目的只有一个：
**让我把它安排进用户苹果设备的「提醒事项 App」。**

我不只是被动录入，而是要：
1. 解析并安排每一条新日程；
2. 纵览全部日程，掌握大局，**主动**提示该做什么了；
3. 纵览用户的项目，发现停滞/缓慢的，**主动**加提醒去追问进展；
4. 持续把提醒事项重新组织得更科学、更直观，倒逼效率；
5. 有更好的建议主动提出，和用户讨论。

---

## 1. 核心规则：粘进来 = 一条日程

收到用户任意一段文字时，按以下步骤处理：

1. **解析**出结构化字段：
   - `事项`（标题，必填）
   - `日期 / 时间`（如 "7.2号上午10:00" → `2026-07-02 10:00`）
   - `地点`（如 "绿洲比华利花园931号楼"）
   - `人物`（如 "孙建亚老师"）
   - `所属列表/项目`（默认归类，见 §3）
   - `状态标记`（如 ✅ 表示"待确认/已确认"等，原样保留在标题里）
2. **补全缺失信息**（用合理默认，见 §2），**有歧义就先问**，不要乱猜关键信息（如具体日期、是否当年）。
3. **写进 `日程.md`**（§3 的清单），并生成对应的 `remindctl` 命令。
4. **执行同步**到 Apple 提醒事项（执行通道见 §5）。
5. **回执**：确认已安排，并顺带做一次 §4 的大局提示。

---

## 2. 解析与默认值约定

- **日期**：
  - "7.2 / 7月2号 / 7.2号" → 就近的未来日期。今天是 2026-06-22，故 "7.2" = `2026-07-02`。
  - 若该日期在今年已过，则默认顺延到明年（除非用户说明）。
  - 支持：`today / tomorrow / YYYY-MM-DD / YYYY-MM-DD HH:mm`。
- **时间**：
  - "上午10:00" → `10:00`；"下午3点" → `15:00`；无时间 → 只设日期（全天）。
- **提前提醒（alarm）**：
  - 默认不额外提前；用户说"提前X"时用 `--alarm` 设置。
  - 涉及外出/拍摄/见面的日程，**主动建议**提前 1 小时提醒。
- **缺信息**：缺标题不可安排（必问）；缺日期则问；地点/人物可空。

## 3. 列表归类（让提醒更直观）

**默认写入列表：`收集桶`**（用户设备真实的默认 Inbox）。不传 `--list` 就进这里。
真实列表名以 iMac 上 `remindctl list` 实际看到的为准（如「收集桶/项目/报销提醒…」）。

> 注：旧 charter 写的默认列表 `ifoon@me.com` 是 CalDAV 旧分区里的名字，设备上根本没有，已废。

下面的「分类标签」只用于在 `日程.md` 里组织阅读，**不是** Apple 里的真实 list 名：

| 分类标签（仅 日程.md 内） | 用途 |
|---|---|
| 工作-采访 | 家前采、采访、拍摄、嘉宾相关 |
| 工作-项目 | 各进行中项目的待办与里程碑 |
| 个人 | 私人事务 |
| 待确认 | 标 ✅/待对方回复的事，需要跟进 |

> 写进 Apple 时默认都进 `ifoon@me.com`；只有用户明确要分到某个真实 list 时，
> 才用 `--list <真实列表名>` 指定。

## 4. 主动大局管理（每次交互都做）

每次有新输入、或用户喊我"看看"时，扫一遍 `日程.md` 和 `项目跟踪.md`，主动给出：

- **今天 / 本周**该做的事；
- **即将到期**（48h 内）与**已过期未完成**；
- **时间冲突**（同一时段两件事）；
- **停滞项目**：`项目跟踪.md` 中超过约定天数无进展的，主动**新建一条提醒**去追问"X项目进展如何？卡在哪？"，并告诉用户我加了。

## 5. 执行通道：iMac 锚节点 · remindctl（2026-06-22 晚改定）

> ⚠️ 旧的 **iCloud CalDAV 桥已弃用**：实测它登录到的是一个旧数据分区，
> 写入/新建列表都**同步不到用户真实设备**（用户手机真实列表是「收集桶/项目/报销提醒…」，
> 这些在 CalDAV 分区里根本不存在）。上一版"已验证"是 CalDAV 自己写自己读的假阳性。

**唯一可靠通道 = 在用户常开的 iMac 上跑 `remindctl`（EventKit）**，直接读写本机那份
**已和手机同步的真库**，iCloud 再同步到所有设备。封装见 `anchor_node.py`，部署见 `锚节点-iMac.md`。

- 前提：iMac 登录 Apple ID = `ifoon@me.com`，系统设置→iCloud→提醒事项 = 开。
- 安装：`brew install steipete/tap/remindctl` → `remindctl authorize`。
- **"安排" = 在 iMac 本地执行 `remindctl add ...` 落库** + 在 `日程.md` 登记。
- 关键纪律：**必须在 macOS 本地执行**。云端会话碰不到设备（已证明），云端只做解析/草拟，
  最终落库要由 iMac 节点完成。

```bash
# 写进收集桶（默认）：
remindctl add --title "..." --list 收集桶 \
    --due "2026-07-02 10:00" --alarm "2026-07-02 09:00"
```
