# 协作与交接协议（iMac ⇄ MacBook Air）

> 两台机器上的会话共用**同一条分支** `claude/teacher-meeting-reminder-yvslkd`。
> 分支 = 唯一真相源。git 不是实时同步，靠下面这套纪律做到"无缝交接"。
> 最后更新：2026-06-22

## 核心原则
1. **分支是唯一真相源**：所有进度只认已 push 到分支上的内容。
2. **本地未 push = 别人看不到**：换机器前，必须先 push；否则那部分工作对另一台机器"不存在"。
3. **`进度.md` 是活状态板**：每次开工先读它，收工前更新它。

## 开工三步（在任意一台机器坐下时）
```bash
git fetch origin
git pull --rebase origin claude/teacher-meeting-reminder-yvslkd   # 拉另一台的最新进度
cat 提醒事项/进度.md                                                # 看到哪了
```
或一条命令：`bash 提醒事项/handoff.sh pull`

## 收工/换机前两步（离开这台机器前）
```bash
# 1) 更新 进度.md 里的"当前状态"（哪台机器、做到哪、下一步）
# 2) 提交并推送
bash 提醒事项/handoff.sh save "简述这次做了什么"
```
**只要离开前 push 了，另一台 pull 一下就是完整现场，无缝接上。**

## 万一两边同时改、push 冲突了
另一台先 push，你 push 被拒（non-fast-forward）时：
```bash
git pull --rebase origin claude/teacher-meeting-reminder-yvslkd   # 把你的改动叠到对方之上
# 如有冲突：手动改完 → git add -A → git rebase --continue
git push
```
> 为减少冲突：`进度.md` / `日程.md` 用**分区块追加**的方式写，两边尽量改不同区块。

## 我（助手）能看到什么 / 看不到什么
- ✅ 看得到：已 push 到分支的一切。
- ❌ 看不到：任一 Mac 上还没 commit/push 的本地改动。
- 所以你让我"理清两边情况"时，我给的是**分支上的合并态**；某台机器的未提交草稿不在其中。
