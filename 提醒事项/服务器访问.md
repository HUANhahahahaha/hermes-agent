# 怎么进那台服务器

> 腾讯云轻量应用服务器（新加坡） · 公网 IP `43.160.249.235` · 内网 `10.3.0.13`
> 登录用户名 `ubuntu` · 主机名 `VM-0-13-ubuntu` · 配置 2核2G / 40GB SSD / 200Mbps
> 队列服务与微信 Clawbot 都跑在这台机器上 —— **它是提醒事项的唯一送达通道。**
>
> 最后更新：2026-08-03

---

## ⚠️ 先看这条

**永远保留两条进得去的路。** 2026-08-03 出过事故：早先出于安全考虑建议删掉腾讯云上的
SSH 密钥，却没同时确认还有别的方式能登录 —— 结果需要重启 gateway 时
`ssh ubuntu@43.160.249.235` 报 `Permission denied (publickey)`，用户一度无法
登录自己的生产服务器。

**带外通道（网页终端）必须始终可用，且事先验证过。** 见下方「路线一」。

---

## 路线一：腾讯云网页终端（不需要 SSH 密钥，救命通道）

密钥丢了、防火墙关错了、SSH 服务挂了 —— 这条路都还在。

1. 浏览器打开腾讯云控制台 → 轻量应用服务器（Lighthouse）实例列表
2. 找到公网 IP 是 `43.160.249.235` 的那台
3. 点右侧的 **「登录」** 按钮 → 打开网页终端
4. 如果提示要密码：在实例详情页里重置一次实例密码，再回来登录
5. 登录成功后，提示符应该是 `ubuntu@VM-0-13-ubuntu`

进去之后常用命令（直接粘贴，不需要改任何东西）：

```
hermes gateway restart
```
```
hermes gateway status
```

## 路线二：SSH（日常用，需先建好密钥）

### 如果 SSH 已经能用

在 **MacBook Air** 上：
```
ssh hermes-vps
```
（`hermes-vps` 是下面配好的别名。没配过别名就用
`ssh -i ~/.ssh/tencent_hermes ubuntu@43.160.249.235`。）

### 如果 SSH 报 `Permission denied (publickey)` —— 重建密钥

**第 1 步｜在 MacBook Air 上**生成密钥，并把公钥打印出来：
```
ssh-keygen -t ed25519 -f ~/.ssh/tencent_hermes -N "" -C "huan-macbook-air"
```
```
cat ~/.ssh/tencent_hermes.pub
```
输出是 `ssh-ed25519 AAAA... huan-macbook-air` 这样的一整行，**整行复制下来**。

**第 2 步｜在腾讯云网页终端里**（路线一进去的那个黑窗口）把公钥装进去。
把下面第二条命令里的 `你复制的那一整行公钥` 换成上一步复制的内容
（引号要留着）：
```
mkdir -p ~/.ssh && chmod 700 ~/.ssh
```
```
echo '你复制的那一整行公钥' >> ~/.ssh/authorized_keys
```
```
chmod 600 ~/.ssh/authorized_keys
```

**第 3 步｜回到 MacBook Air**，验证能进：
```
ssh -i ~/.ssh/tencent_hermes ubuntu@43.160.249.235
```
看到提示符变成 `ubuntu@VM-0-13-ubuntu` 就是成功了。输入 `exit` 退出。

**第 4 步｜还在 MacBook Air 上**，配个别名，以后只要打 `ssh hermes-vps`：
```
cat >> ~/.ssh/config <<'EOF'

Host hermes-vps
    HostName 43.160.249.235
    User ubuntu
    IdentityFile ~/.ssh/tencent_hermes
EOF
```

## ⛔️ 常见误操作

**不要**把 `hermes gateway restart` 这类命令跑在 MacBook Air 自己的终端里。
那会在 MBA 上另起一个 gateway，和 VPS 上的实例争抢同一个微信登录态，报
`Session expired; pausing for 10 minutes` —— 2026-08-03 真实发生过。

判断方法：**看提示符**。
- `huan@HuandeMacBook-Air ...` → 这是你自己的电脑，**不要**在这儿跑 hermes 命令
- `ubuntu@VM-0-13-ubuntu ...` → 这才是服务器

从 MBA 的提示符切到服务器：跑 `ssh hermes-vps`。
从服务器退回自己电脑：跑 `exit`。

## 排查用的只读命令（都在服务器上跑，安全）

看 gateway 在不在：
```
hermes gateway status
```

看最近的 API 调用记了什么模型和 provider（消费日报报 0 时先看这个）：
```
grep "API call #" ~/.hermes/logs/agent.log | tail -20
```
输出里如果是 `provider=unknown`，说明 provider 没配 —— 见
`待办清单.md` 里「第三个根因」。

看队列里还有什么没被认领（**只读，安全**）：
```
curl -s -H "X-Queue-Token: $(cat ~/.reminder-queue/token)" http://127.0.0.1:8787/pending
```

> ⛔️ **绝不要 `curl .../claim`** —— 那是「认领即出队」，一读就把用户手机还没
> 收到的提醒吃掉。查看永远用 `/pending`。
