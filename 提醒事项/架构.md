# 提醒事项写入架构（现役，勿再造轮子）

> **这是唯一能把提醒送到用户 iPhone 的链路。** 2026-07-28 由用户提供的
> 快捷指令截图确认。此前因为这套架构没被记录，导致一整轮工作走了 CalDAV
> 死路 —— 读这份文件再动手。

## 全链路

```
微信 Clawbot ──入队──▶  队列服务 43.160.249.235:8787
                              │
                              │  GET /claim  （快捷指令定期拉取并认领）
                              ▼
                    Apple 快捷指令（用户 iPhone）
                              │  解析 title / due / notes
                              ▼
                    提醒事项「收集桶」列表 ──▶ 用户看得到 ✅
```

## 快捷指令做了什么（截图逐条还原）

1. `获取 http://43.160.249.235:8787/claim 内容`
2. `重复 URL 的内容中的每一项`：
   - 取 `title` 的值
   - 取 `due` 的值
   - 取 `notes` 的值
   - `从字典值获取日期`（把 `due` 转成日期对象）
   - `将字典值添加到 收集桶（日期）` ← 写入提醒事项
3. `结束重复`
4. `停止并输出 重复结果`；无输出时不执行任何操作

## 队列返回的数据格式

`GET /claim` 返回一个数组，每项至少含三个字段：

```json
[
  {"title": "孙建亚老师 家前采时间确认", "due": "2026-07-02 10:00",
   "notes": "地点：绿洲比华利花园931号楼"}
]
```

- `/claim` 语义是**认领**：取走即出队，重复调用不会拿到同一条。
- ⚠️ **不要为了调试去 GET `/claim`** —— 会把待写入的条目消费掉，
  用户手机就再也收不到那几条了。

## 要新增一条提醒，该怎么做

**往队列入队即可**，不要碰用户手机、不要用 CalDAV、也不必用 remindctl。

- 入队接口：**待确认**（截图只覆盖消费端 `/claim`；生产端由微信 Clawbot
  已在使用，端点名未记录）。
- 确认方式：问用户，或看那台队列服务的代码/路由表。

## 已知死路（别再试）

| 通道 | 结论 |
|---|---|
| iCloud CalDAV | ❌ 苹果 2019 年（iOS 13/Catalina）把提醒事项迁进私有仓库，CalDAV 侧只剩一个用户看不到的废仓库。实测：CalDAV 写入的条目手机上不可见；微信写入的条目 CalDAV 里查不到。 |
| 本容器直连队列 | ❌ 43.160.249.235:8787 不在网络白名单内，从云端会话连不上（也不需要连）。 |
