### 真正的卡点（2026-06-22 会话定位）
依赖已装、凭据有效、`caldav.icloud.com` 已能连通且**认证成功**
（principal 发现 OK，账号 ID = `1056422635`）。但 iCloud 把真正的提醒数据
放在**按账号分区的主机**上，本账号是 `p133-caldav.icloud.com`。
当前白名单 `caldav.icloud.com` + `*.caldav.icloud.com` **匹配不到它**——
注意 `p133-caldav` 与 `caldav` 之间是连字符不是点，所以 `*.caldav.icloud.com`
不覆盖 `p133-caldav.icloud.com`。直连验证结果：
```
caldav.icloud.com        -> 403 AppleHttpServer（真实 Apple 服务器，正常）
p133-caldav.icloud.com   -> Host not in allowlist（被网络出口拦截）
```
所以 `sync.py lists` 报的 Forbidden **不是 App 专用密码问题**，是网络白名单缺分区主机。

### 下一步
1. 让用户在 **网络出口设置**里补上分区主机（任选其一，越靠上越精准）：
   - `p133-caldav.icloud.com`（当前账号的分区主机，最小授权）
   - `*-caldav.icloud.com`（覆盖所有分区主机，iCloud 偶尔会换分区，更稳）
   - `*.icloud.com`（最宽松）
   说明：白名单改动**只对新会话生效**，改完必须**再开一个新会话**。
2. 新会话里装依赖（新会话不带上次手动 pip 的包）：
   ```bash
   pip install caldav icalendar
   ```
3. 验证连通：
   ```bash
   python3 提醒事项/sync.py lists
   ```
   - 能列出提醒事项列表 = 全链路打通。
   - 若仍报 `Host not in allowlist: p<NN>-caldav.icloud.com` = 分区主机没加对/规则没生效。
   - 若 `caldav.icloud.com` 这层就报认证失败 = 才轮到 App 专用密码问题，让用户重新生成。
4. 打通后，把第一条真实写入用户手机验证：
   ```bash
   python3 提醒事项/sync.py add \
     --title "孙建亚老师 家前采时间确认（绿洲比华利花园931号楼）" \
     --list "工作-采访" --due "2026-07-02 10:00" --alarm "2026-07-02 09:00"
   ```
   （`--list` 名按用户实际列表调整；先用 `lists` 看真实列表名。）
